# 思考・タスク整理アプリ「ツール」 たたき台 v0.2

> v0.1の未確定事項はすべて確定済み(9章)。このバージョンからClaude Codeに渡せる。

## 0. 一行サマリー

**「白紙に書く」のではなく「型(箱)を埋める」ことで、タスクの受け取りミスと思考の迷子をなくす、PCローカル完結の完全個人用アプリを作る。**

## 1. 課題(Why) ― 空・雨・傘で整理

**空(事実)**
- 上司から振られたタスクの成果物が、意図とズレることがある
- 話を聞きながらメモを取るのが苦手で、目的・完成形・期限が記録に残らない
- 議事録の作成も苦手(発言を全部書こうとして追いつかなくなる)
- 既存のメモアプリは白紙の自由帳型で、書き始めても構造化されずまとまらない

**雨(解釈)**
- 問題は「書く能力」ではなく、**何を書くべきかが毎回白紙から始まること**。埋めるべき箱が最初から見えていれば、キーワードを放り込むだけで足りる
- ズレ対策の型(4つの箱・空雨傘・30%ドラフト・提出前3問)は決まっているのに、運用する仕組みがないので定着しない

**傘(行動)**
- 型そのものをアプリのUIとして実装する。「型を思い出して使う」から「**アプリを開いたら型しかない**」へ

## 2. 解決コンセプト(What)

コンセプト: **考える前に、箱が出てくるアプリ。**

- 新規作成すると白紙ではなく、目的別のテンプレ(箱)が表示される
- 埋まらなかった箱 = 「上司に確認すべきこと」として自動で可視化される
- 記録がそのままタスク一覧になり、進み具合(ステータス)を追える

### 主なユースケース

1. **タスクを振られた直後(最重要)**: 席に戻ってすぐPCで「タスク受信」を開き、目的/完成形/期限/疑問点 の4箱にキーワードを放り込む。所要1分以内
2. **考えを整理したいとき**: 空雨傘テンプレで書く。必要ならタスクに紐付ける
3. **提出前**: タスク詳細の3問チェック(目的に答えてる? / 結論は10秒で見つかる? / 相手の次アクションが明確?)を通してから出す
4. **会議のとき(Phase 3)**: 議事録モードで録音しながら、決定・TODO・論点だけ書く
5. **行き詰まったとき(Phase 2)**: AI壁打ちで「So what?」のツッコミをもらう

## 3. 機能要件

### Phase 1(MVP) ― まずここまで作る

| ID | 機能 | 内容 |
|----|------|------|
| F1 | タスク受信箱 | タイトル + 4箱(目的/完成形/期限/疑問点)。疑問点は複数登録でき、1件ずつ「解決済み」にできる |
| F2 | タスク一覧 | 期限順表示。ステータス(受領/作業中/30%確認済/完了)。未解決の疑問が残るタスクに「要確認」バッジ |
| F3 | 空雨傘メモ | 事実/解釈/行動 の3枠。タスクへの紐付けは任意 |
| F4 | 提出前チェック | 3問にチェックを入れて「完了」にする(強制はしない、スキップも可) |
| F5 | 保存とバックアップ | ブラウザ内(IndexedDB)に永続保存。全データをJSONで書き出し/読み込みできる(バックアップ手段) |

### Phase 2(MVP完成後)

- **議事録テンプレ**: 決定事項 / TODO(担当・期限) / 論点(未決) の3箱 + 日時・参加者。逐語録は書かない設計
- **結論ファースト下書き**: 結論1行 → 根拠3つ → 肉付け のアウトライナー
- **ブレストモード**: タイマー + 件数カウンタ、批判禁止バナー、カードのグルーピング(KJ法)
- **AI壁打ち(Gemini API)**: So what? ツッコミ役 / 30%ドラフトのレビュー役

### Phase 3 ― 録音同期つき議事録モード

- 会議の録音とメモ入力を時刻で同期。書いたブロックをクリックすると、**その約15秒前から**録音を再生する(人は「聞いた後に」書くため、記録時刻ぴったりだと発言を過ぎている)
- 役割分担の思想: **録音が「空(事実)」を全部引き受け、人間は雨・傘(決定・TODO・論点)だけ書く**。逐語メモからの解放が目的
- 実装の骨子: MediaRecorder APIで録音 → 各ブロックに「録音開始からの経過時間(offsetMs)」を記録 → クリックで `audio.currentTime = offsetMs/1000 - 15`
- **録音仕様(確定)**: 軽さ優先、ただし将来の文字起こしに支障がない下限を守る
  - モノラル / サンプリングレート16kHz以上 / Opus 32kbps目安(1時間 ≒ 15MB)
  - 音声認識(Whisper等)は16kHzモノラルが標準入力のため、この設定なら文字起こしにそのまま使える
- 技術メモ:
  - 音声はIndexedDBにBlobで保存
  - 長時間録音はタイムスライスで分割保存し、途中クラッシュしても失わないようにする
  - Web会議(Teams等)をPCで録る場合、マイクだけだと相手の音声を拾いにくい。必要になったらタブ/システム音声のキャプチャ(getDisplayMedia)を検討(将来課題)

### やらないこと(Non-goals)

- チーム共有・多人数利用(完全に個人用)
- 端末間同期・クラウド保存(ローカル完結。バックアップはF5のJSON書き出しで対応)
- 通知・リマインダー(まず作らない。欲しくなったら再検討)
- デザインの作り込みで時間を溶かすこと。「毎日開ける速さ」を優先

## 4. 画面ラフとUI方針

画面は3つだけ。

```
[ホーム/タスク一覧]        [タスク詳細]            [メモ作成]
+------------------+   +------------------+   +------------------+
| 期限順リスト      |   | タイトル          |   | テンプレ選択      |
|  ・資料A [要確認] | → | 目的    [      ] |   |  (空雨傘 / 自由)  |
|  ・議事録B       |   | 完成形  [      ] |   | 空(事実) [     ] |
|  ・調査C [30%済] |   | 期限    [      ] |   | 雨(解釈) [     ] |
|                  |   | 疑問点  ・… [✓] |   | 傘(行動) [     ] |
| [+タスク] [+メモ] |   | メモ一覧 / 3問    |   | 紐付け: 資料A    |
+------------------+   +------------------+   +------------------+
```

UI方針:

- **シンプル・ミニマル(Googleのサービスのような見た目)**。白基調・余白広め・装飾は最小限。凝ったアニメーションは入れない
- **キーボード完結を最優先**(入力が主用途のため): Tabで箱を順に移動、Ctrl+Enterで保存、`n`で新規タスクなどのショートカット
- 入力画面は1画面1目的。箱を埋める以外の要素を置かない

## 5. 技術構成(How) ― 確定

- **フロント**: React + Vite + TypeScript + Tailwind
- **データ**: IndexedDB(ブラウザ内DB)。サーバーなし・外部送信なしのローカル完結
- **実行**: 自宅PCのWSL2(Ubuntu)でビルドし、ブラウザから localhost で利用。`npm run app` のような1コマンド(エイリアス)で起動できるようにする
- **注意**: ブラウザのデータ消去でIndexedDBも消えるため、JSON書き出し(F5)を定期バックアップとして運用する

用語メモ: **IndexedDB** = ブラウザの中にある保存領域。サーバーがなくてもデータを永続化できる。

### 開発の進め方

- Claude Code の `/loop`(goal-locked-loop)で回す前提。受け入れ基準(7章)は目標契約にそのまま流用できる形で書いてある
- 機能単位(F1 → F2 → …)で実装し、各機能ごとに受け入れ基準を検証してから次へ進む

## 6. データモデル(案)

```ts
type TaskStatus = "received" | "in_progress" | "draft_reviewed" | "done";
// 受領 / 作業中 / 30%確認済 / 完了。
// 「要確認」はステータスではなく、未解決 question の有無から自動判定する

interface Task {
  id: string;
  title: string;
  purpose: string;        // 目的: 何のため
  deliverable: string;    // 完成形: どんな形で出す
  deadline?: string;      // 期限(ISO日付)。未定も許可
  questions: { id: string; text: string; resolved: boolean }[]; // 疑問点
  status: TaskStatus;
  submitCheck: {          // 提出前3問
    answersPurpose: boolean;      // 目的に答えているか
    conclusionIn10s: boolean;     // 結論は10秒で見つかるか
    nextActionClear: boolean;     // 相手の次アクションが明確か
  };
  createdAt: string;
  updatedAt: string;
}

interface Memo {
  id: string;
  taskId?: string;            // 任意でタスクに紐付け
  type: "soraamekasa" | "free";
  fact?: string;              // 空: 事実
  interpretation?: string;    // 雨: 解釈
  action?: string;            // 傘: 行動
  body?: string;              // 自由メモ用
  createdAt: string;
}

// Phase 2/3 で追加予定(着手時に詳細化):
// Meeting(議事録) / MinuteBlock(決定・TODO・論点の各ブロック + offsetMs) / Recording(音声Blob + 開始時刻)
```

## 7. 受け入れ基準(MVP完了の定義)

第三者が yes/no で判定できる形にしてある。全部 yes で MVP 完了。

1. PCのブラウザで、タスク新規作成 → 4箱入力 → 保存 → 一覧表示 → ステータス変更 → 完了 まで一連の操作ができる
2. 未解決の疑問点が1件以上あるタスクには一覧上に「要確認」バッジが表示され、全件解決すると消える
3. 空雨傘メモを作成してタスクに紐付けられ、タスク詳細画面からそのメモを参照できる
4. ブラウザを完全に終了して再起動しても、登録済みデータが全件残っている
5. 全データをJSONファイルとして書き出せ、データ全削除後にそのJSONを読み込むと元の状態に復元される
6. マウスを使わず、キーボードだけ(Tab移動 + ショートカット)でタスク登録から保存まで完了できる
7. 1コマンド(またはショートカット1つ)でアプリを起動し、ブラウザからアクセスできる

## 8. 制約・運用上の注意

- MVP(Phase 1)は外部にデータを一切送信しない(通信ゼロのローカル完結)
- Phase 2のAI壁打ちで初めて外部送信(Gemini API)が発生する。**壁打ちに送る内容には業務の機密・顧客固有情報を含めない**運用にする
- 業務上の固有情報は、アプリ内でも自分がわかる抽象度で書く運用を推奨
- 録音の運用ルールは確認済み(問題なし)。録音データはローカル保存のみで外部に送らない
- ブラウザのデータ消去に備え、JSON書き出しで定期バックアップする

## 9. 確定事項(v0.1の未確定事項への回答)

1. **アプリ名**: 「ツール」(名前にはこだわらない方針)。リポジトリ名は `tool` などで可
2. **構成**: A案で確定。PCローカル(ブラウザ + IndexedDB)、同期なし
3. **入力の主戦場**: PCから入力
4. **ステータス**: 4段階(受領/作業中/30%確認済/完了)で確定
5. **AI壁打ち**: Gemini APIを利用予定(モデル・プランの選定はPhase 2着手時)
6. **録音**: 運用上問題なしと確認済み。音質は軽さ優先、ただし将来の文字起こしに支障がない仕様(モノラル/16kHz以上/Opus 32kbps目安)

残る検討事項(着手時でよいもの): Geminiのモデル選定(Phase 2) / Web会議の相手音声の扱い(Phase 3)
